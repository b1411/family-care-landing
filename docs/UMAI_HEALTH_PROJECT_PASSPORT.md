## 1. СУТЬ ПРОДУКТА

**UMAI Health** — B2B SaaS-платформа для частных клиник, обеспечивающая полный цифровой маршрут сопровождения семьи **от момента наступления беременности до 2 лет ребёнка**.

Платформа работает по модели **B2B2C**: клиника подключает платформу, настраивает под свой бренд (white-label), а семьи получают доступ как пациенты этой клиники.

### Проблема, которую решает UMAI Health

Частные клиники Казахстана теряют семьи как клиентов после родов. Стандартный сценарий:
- Беременная пациентка регулярно посещает клинику 9 месяцев
- После родов «исчезает» — без напоминаний, без связи
- Переходит на педиатрическое обслуживание в другое место
- Клиника теряет выручку от 2 лет педиатрического сопровождения

С другой стороны, семья остаётся один на один с потоком информации: расписание прививок, назначения витаминов, скрининги, контрольные визиты — без единой системы управления.

**UMAI Health** закрывает этот разрыв с двух сторон одновременно:
- Для клиники: инструмент удержания и монетизации семьи на 2+ года
- Для семьи: цифровой ассистент, который ведёт по маршруту от беременности до двухлетия

### Ключевые числа маршрута

| Этап | Период | Ключевые события |
|------|--------|------------------|
| Беременность | 40 недель | 10–12 визитов к гинекологу, 3 УЗИ, 15+ анализов, скрининги |
| Послеродовой | 0–3 месяца | Неонатальные осмотры, первые прививки, EPDS-скрининг мамы |
| Грудничковый | 3–12 месяцев | Педиатрические осмотры 1×/мес, вакцинация по НК, ввод прикорма |
| Ранний возраст | 12–24 месяца | Плановые осмотры, ревакцинация, оценка развития по ВОЗ |

Итого: **50+ запланированных событий** на каждую семью в течение 2 лет.

## 3. ЦЕННОСТНОЕ ПРЕДЛОЖЕНИЕ

### Для клиники (B2B)

| Проблема | Решение UMAI Health |
|----------|-------------------|
| Семьи уходят после родов | Автоматический маршрут 0–2 года удерживает семью в клинике |
| Координаторы тонут в Excel | Умная очередь задач с приоритетами вместо таблиц |
| Пропущенные назначения снижают NPS | Push/WhatsApp уведомления о каждом событии маршрута |
| Нет данных для управления | Аналитика: удержание, соблюдение назначений, LTV, NPS |
| Трудно масштабировать без роста штата | Автоматизация CRM: воронка лидов, сегменты, кампании |
| Нет контроля качества медицины | Модуль главврача: протоколы, отклонения, Rx-аудит |

**Полный цикл монетизации:**
- Беременность (9 месяцев × визиты = высокий чек)
- Роды (highest check)
- Педиатрия 0–2 года (повторная выручка 24 месяца)
- Сервисные пакеты: подписка «Медицинское сопровождение семьи»

### Для семьи (B2C через клинику)

- **Маршрут в телефоне** — все 50+ событий разложены по датам
- **Не пропустить прививку** — казахстанский национальный календарь, автоматические даты
- **Все документы в одном месте** — анализы, УЗИ, выписки, рецепты (фото + PDF)
- **Ответы на вопросы 24/7** — AI-ассистент Care AI (на базе GPT-4o-mini)
- **Координатор всегда на связи** — чат с ответом в течение 30 минут
- **Здоровье ребёнка под контролем** — графики роста, EPDS, трекер настроения

### Подробное описание каждой роли

#### 4.1 Семья (mother/father)

**Интерфейс:** Мобильное приложение (mobile-first, bottom navigation)

**Что видит:**
- Главный экран: текущая неделя/месяц беременности или возраст ребёнка, ближайшие 3 события, назначения на сегодня
- **Маршрут:** Вертикальный timeline всех 50+ событий (визиты, анализы, прививки, назначения)
- **Записи:** История и предстоящие приёмы, возможность записаться
- **Документы:** Архив с категориями (анализы, УЗИ, выписки, прививки), поиск, загрузка фото
- **Прививки:** Национальный календарь с датами и статусами
- **ИИ-ассистент:** Чат Care AI — вопросы о здоровье, питании, развитии ребёнка
- **Здоровье-паспорт:** Хронология всех медицинских событий ребёнка
- **Рост:** Графики по перцентилям ВОЗ (вес, рост, окружность головы)
- **Настроение:** Ежедневный трекер + EPDS-скрининг депрессии
- **SOS:** Экстренная помощь с триажом симптомов
- **Достижения:** Геймификация — значки, стрики, баллы лояльности

#### 4.2 Координатор

**Интерфейс:** Веб-консоль (desktop-first)

**Что видит:**
- **Дашборд:** Метрики клиники (активные семьи, просроченные события, задачи на сегодня)
- **Очередь задач:** Приоритизированные задачи (красный/оранжевый/зелёный) с фильтрами по статусу и этапу маршрута. Типы: приветственный звонок, просроченный визит, низкая приверженность, напоминание о прививке, реактивация
- **Семьи:** Список с прогрессом маршрута, фильтрация, поиск, 360°-профиль каждой семьи
- **Outreach:** Автоматические сценарии уведомлений, логи рассылок

#### 4.3 Врач (Доктор)

**Интерфейс:** Веб-консоль

**Что видит:**
- **Сегодня:** Расписание приёмов, пациенты дня
- **Пациенты:** Список с хронологией, назначениями, adherence%
- **Расписание:** Управление слотами
- **Рецепты:** Создание назначений с INN, дозировкой, маршрутом введения, ICD-10
- **Документы:** Загрузка и просмотр мед.документов пациентов
- **Планы ухода:** Управление маршрутами
- **Отклонения:** Уведомления о нарушениях протоколов

#### 4.4 Главный врач

**Интерфейс:** Веб-консоль (read-heavy, контроль качества)

**Что видит:**
- **Дашборд:** KPI качества — compliance %, просроченные протоколы, активные отклонения
- **Протоколы:** Библиотека клинических протоколов (по ICD-10), управление версиями, подтверждение врачами
- **Отклонения:** Отклонения от протоколов по назначениям и визитам
- **Rx-аудит:** Контроль полифармации, анализ назначений по INN
- **Жалобы:** Входящие жалобы с разбором
- **Разбор случаев:** Кейс-менеджмент с детальным анализом
- **Врачи:** Мониторинг производительности врачей (приёмы, рейтинг, выручка)

**Важно:** Главный врач имеет права только на **чтение** всех данных клиники. Запись возможна только для собственных сущностей (протоколы, разборы случаев, комментарии к отклонениям).

#### 4.5 Администратор клиники

**Интерфейс:** Веб-консоль (полный доступ)

**Что видит:**
- **Дашборд:** KPI (MAU, Retention 6 мес, LTV, NPS), выручка по месяцам
- **Семьи:** Полный список с 360°-профилем
- **Врачи:** Управление врачами, специальностями
- **Координаторы:** Управление персоналом
- **Аналитика:** Когортный анализ, heatmap удержания, воронка конверсии
- **Лиды:** CRM-воронка (new → contacted → interested → negotiation → won/lost)
- **Сделки:** Финансовый pipeline
- **Кампании:** Email/SMS/Push кампании по сегментам
- **Сегменты:** Умные сегменты семей (по этапу, LTV, риску ухода)
- **Пакеты услуг:** Управление подписочными продуктами
- **Интеграции:** Подключение внешних систем
- **Репутация:** Управление отзывами на 2GIS, Google
- **Сеть:** Управление сетью клиник
- **Комплаенс:** Соответствие требованиям
- **Обучение:** Модули онбординга для персонала
- **Настройки:** White-label, брендирование, тема

## 5. ФУНКЦИОНАЛЬНЫЕ МОДУЛИ

### 5.1 Care Plan Engine — Движок маршрутов

Ключевой модуль платформы. Автоматически генерирует **персональный маршрут** семьи на основе:
- Дата последней менструации (ДПМ) → вычисляет предполагаемую дату родов (ПДР) и все даты визитов беременности
- Дата рождения ребёнка → вычисляет все педиатрические осмотры и даты вакцинации

**Journey Types (типы маршрутов):**
- `pregnancy` — беременность (40 недель)
- `postpartum` — послеродовой период (0–3 месяца)
- `infant` — грудничковый (3–12 месяцев)
- `toddler` — ранний возраст (12–24 месяца)

**Event Types (типы событий):**
- `consultation` — визит к врачу
- `screening` — скрининг
- `analysis` — анализ
- `ultrasound` — УЗИ
- `vaccination` — прививка
- `checkup` — осмотр
- `specialist` — специалист
- `prescription_start` — начало приёма препарата
- `milestone` — этап развития
- `custom` — пользовательское событие

**Journey Templates** — шаблоны маршрутов, которые клиника может настраивать под свои протоколы. Есть глобальные (дефолтные) и клинические (per-clinic).

**Supabase Edge Function** `generate-care-plan` — автоматически создаёт полный набор `journey_events` на основе шаблона и дат семьи.

### 5.2 Система уведомлений

Multi-channel уведомления по каждому событию маршрута:

| Канал | Статус | Когда используется |
|-------|--------|-------------------|
| `in_app` | ✅ | Push внутри приложения |
| `push` | ✅ | Web Push (FCM) через токены |
| `whatsapp` | ✅ | WhatsApp Business API |
| `sms` | ✅ | SMS через провайдеров |
| `email` | ✅ | Через Resend |

**Supabase Edge Function** `send-notification` — обрабатывает очередь уведомлений.
**Supabase Edge Function** `daily-status-check` — запускается каждый день, создаёт задачи координатора по просроченным событиям.

### 5.3 Координаторская очередь задач

Задачи создаются автоматически системой при:
- Пропущенном визите
- Низком adherence (соблюдении назначений)
- Просроченной прививке
- EPDS-скрининге с высоким риском
- Реактивации неактивной семьи

**Task Types:**
```
welcome_call       — приветственный звонок новой семье
overdue_followup   — просроченный повторный визит
missed_appointment — пропущенная запись
low_adherence      — низкое соблюдение назначений
vaccination_reminder — напоминание о прививке
reactivation       — реактивация неактивной семьи
epds_alert         — тревога по EPDS (риск ПРД)
custom             — пользовательская задача
```

**Приоритеты:** `critical` → `high` → `medium` → `low`

### 5.6 AI-ассистент Care AI

**Технология:** OpenAI GPT-4o-mini

**Ограничения (жёсткие правила):**
- НИКОГДА не ставит диагнозы
- НИКОГДА не назначает лекарства или дозировки
- При тревожных симптомах (температура >39°C, судороги, затруднённое дыхание) — настоятельно рекомендует скорую
- Отвечает только на вопросы, связанные с детским здоровьем и родительством
- Всегда заканчивает: «Для точной оценки проконсультируйтесь с вашим врачом»
- Контекст ребёнка (имя, возраст, пол) передаётся в system prompt

**Хранение:** История разговоров в `ai_conversations`, обратная связь в `ai_feedback`

### 5.7 EPDS-скрининг послеродовой депрессии

Встроена **Эдинбургская шкала постнатальной депрессии (EPDS)** — 10 вопросов, стандарт ВОЗ.

Вопросы охватывают: радость, тревогу, самообвинение, панику, ощущение неспособности справляться, плач, мысли о самовреждении.

**Результат:**
- `low` — без риска
- `moderate` — умеренный риск, мониторинг
- `high` — высокий риск → автоматическая задача координатора с типом `epds_alert`

### 5.8 Трекинг роста (ВОЗ)

Графики роста по перцентилям ВОЗ:
- Вес (кг)
- Рост/длина тела (см)
- Окружность головы (см)

Отображаются кривые P3, P15, P50, P85, P97.

### 5.9 CRM и воронка лидов

Полноценная CRM для клиники:

**Источники лидов:**
`website`, `instagram`, `2gis`, `referral`, `walk_in`, `phone`, `whatsapp`, `other`

**Стадии воронки:**
```
new → contacted → interested → negotiation → won → lost
```

**Lead Activities** — история взаимодействий:
`call`, `whatsapp`, `sms`, `email`, `note`, `meeting`, `demo`, `status_change`

**Family Activities** — 360°-история семьи:
- Звонки, сообщения, встречи
- Записи и визиты
- Назначения и документы
- Изменения статуса в маршруте

### 5.10 Аналитика

**Для администратора клиники:**
- MAU (Monthly Active Users)
- Retention по когортам (heatmap по месяцам поступления)
- LTV на семью
- NPS (Net Promoter Score)
- Воронка конверсии
- Выручка по месяцам, врачам, типам услуг

**Аналитические представления (Views):**
- `v_clinic_dashboard` — обзор клиники (активные семьи, маршруты, просроченные события, задачи, соблюдение %, месячная выручка)
- `v_doctor_performance` — производительность врача (приёмы, no-show, рейтинг, выручка)

**Supabase Edge Function** `calculate-analytics` — агрегирует метрики для дашборда.

### 5.11 Модуль главного врача (Медицинское качество)

Введён в Migration 019+ для роли `chief_doctor`.

**Клинические протоколы:**
- Библиотека протоколов, привязанных к ICD-10 кодам
- Управление версиями (v1, v2...)
- Обязательный чеклист визита (жалобы, осмотр, диагноз, план, рекомендации)
- Ожидаемые INN препаратов, запрещённые INN
- Порог полифармации (max_prescriptions)
- Ожидаемое время повторного визита
- Подтверждение врачами (protocol_acknowledgements)

**ICD-10 справочник** — встроен стартовый набор казахстанских приоритетов:
- Беременность и роды: O09–O82
- Послеродовой: O90–F53
- Педиатрия: Z00.1, Z23, P07, P59
- Острые: J06, J20, A08, R50
- Хронические: L20, J45, E66

**Rx-аудит:**
Структурированные рецепты с полями: `inn_name`, `dose_value`, `dose_unit`, `route`, `icd10_indication`

**Отклонения от протоколов** — автоматически фиксируются при:
- Визите без полного чеклиста
- Назначении запрещённого INN
- Превышении порога полифармации
- Пропуске обязательного follow-up

### 5.12 White-label (Брендирование)

Каждая клиника получает собственный бренд:
- Собственный логотип
- Кастомная цветовая схема (`theme_json`)
- Уникальный slug (поддомен)
- Настройки часового пояса
- Ссылки на отзывы (2GIS, Google)

### 5.13 Геймификация и лояльность

Для повышения вовлечённости семьи:

- **Достижения (Achievements)** — бейджи за выполненные события: «Первая прививка», «3 месяца streak», «100% прививок» и др.
- **Стрики (Streaks)** — серии ежедневного приёма витаминов, визитов
- **Баллы лояльности** — начисляются за выполненные события маршрута
- **Реферальная программа** — семья приводит другую семью в клинику

### 5.14 Видеоконсультации

Встроенная телемедицина:
- Видеозвонок врач ↔ семья
- Привязка к записи на приём
- Запись звонка
- Статусы: scheduled, in_progress, completed, cancelled, missed

### 5.15 Пакеты услуг

Клиника создаёт подписочные продукты:
```
service_packages  — описание пакета, цена, срок (мес)

```

### Обзор схемы (33 миграции)

PostgreSQL (Supabase) с **Row Level Security (RLS)** на каждой таблице.

#### Ядро системы

```
clinics                  — мультитенантная основа (1 клиника = 1 tenant)
users                    — расширение Supabase auth.users (id, role, clinic_id)
families                 — семья (primary_parent + optional secondary_parent)
mother_profiles          — профиль мамы (ДПМ, ПДР, группа крови, аллергии)
child_profiles           — профиль ребёнка (ДР, пол, вес при рождении, рост, Апгар)
```

#### Journey Engine (маршруты)

```
journey_templates        — шаблоны (pregnancy/postpartum/infant/toddler)
journeys                 — активные маршруты семьи
journey_events           — события маршрута (50+ штук)
```

#### Медицинские данные

```
doctors                  — врачи клиники
appointment_slots        — слоты расписания врача
appointments             — записи на приём (+ ICD-10, чеклист)
documents                — медицинские документы
prescriptions            — назначения (+ INN, доза, маршрут введения)
dose_logs                — история приёма лекарств (pending/confirmed/missed)
vaccinations             — прививки (по НК Kazakhstan)
health_passport_entries  — записи в паспорт здоровья ребёнка
```

#### Операции

```
coordinator_tasks        — задачи координатора (с приоритетом и типом)
notifications            — уведомления (все каналы)
visit_ratings            — оценки визитов (1–5)
service_transactions     — финансовые транзакции
```

#### Аналитика (Views)

```
v_clinic_dashboard       — обзор клиники
v_doctor_performance     — производительность врачей
```

#### Engagement (вовлечённость)

```
achievements             — справочник достижений

streaks                  — серии (тип, текущий, максимальный)
referrals                — реферальная программа
loyalty_points           — баллы лояльности
nps_responses            — NPS ответы (0–10)
```

#### B2B / Клиника

```
service_packages         — пакеты услуг
family_packages          — подписки семей
outreach_scenarios       — сценарии автоматических коммуникаций
outreach_logs            — история рассылок
review_requests          — запросы на отзыв
training_modules         — обучающие модули для персонала

```

#### CRM

```
leads                    — лиды (6 стадий воронки)
lead_activities          — история взаимодействий с лидом
family_activities        — 360° история семьи (18 типов событий)
segments                 — сегменты семей
campaigns                — маркетинговые кампании
deals                    — финансовые сделки
message_templates        — шаблоны сообщений
```

#### Клинические (Chief Doctor)

```
icd10_codes              — справочник МКБ-10 (стартовый набор KZ)
clinical_protocols       — клинические протоколы (по ICD-10)
protocol_acknowledgements— подтверждение протоколов врачами
prescriptions (расширен) — INN, доза, маршрут введения, ICD-10, связь с приёмом
appointments (расширен)  — ICD-10 первичный/вторичный, чеклист визита
```

#### Расширенные модули

```
ai_conversations         — история AI-диалогов
ai_feedback              — оценка ответов AI
video_consultations      — видеоконсультации
mood_logs                — трекер настроения (1–5, уникальный на пользователя/день)
epds_screenings          — EPDS-скрининги (10 вопросов, риск low/moderate/high)
```

### RLS (Row Level Security)

Каждая таблица защищена RLS. Ключевые хелпер-функции:

```sql
get_user_role()          → текущая роль пользователя
get_user_clinic_id()     → ID клиники пользователя
is_staff()               → coordinator, doctor, admin и их варианты
is_chief_doctor_of(clinic_uuid) → является ли главврачом клиники
```

**Принципы изоляции:**
- Семья видит **только свои** данные
- Персонал видит данные **только своей клиники**
- Данные разных клиник **полностью изолированы**
- Главный врач имеет **только read** доступ к клиническим данным

## 12. БЕЗОПАСНОСТЬ И СООТВЕТСТВИЕ ТРЕБОВАНИЯМ

### Архитектура безопасности

**Row Level Security (RLS):**
- Включён на каждой таблице базы данных
- Семья видит только свои данные
- Персонал — только данные своей клиники
- Данные клиник полностью изолированы друг от друга
- Платформенные администраторы — доступ ко всему

**Аутентификация:**
- Supabase Auth (JWT)
- Tokens httpOnly cookies (не localStorage)
- Глобальный middleware проверяет авторизацию и роль

**Роль-based доступ (RBAC):**
```
/family    → mother, father
/coordinator → coordinator, admin
/doctor    → doctor, gynecologist, pediatrician, nurse, admin
/chief     → chief_doctor, admin
/admin     → clinic_admin, clinic_manager, platform_admin, admin, superadmin
```

**Сервер API:**
- Каждый серверный роут проверяет `serverSupabaseUser(event)`
- Zod-валидация всех входящих данных
- Rate limiting (через Vercel Edge)

**Demo-режим (read-only):**
- Plugin `02.demo-readonly.client.ts` блокирует все мутации
- Демо-аккаунты не могут изменять реальные данные

**Аудит лог:**
- Migration 026 добавляет тригеры на всех критичных таблицах
- Все изменения логируются с `user_id`, `timestamp`, `old_value`, `new_value`

### Соответствие требованиям

- Страница `/privacy` — Политика конфиденциальности
- Страница `/terms` — Условия использования
- Страница `/security` — Описание мер безопасности
- Consent management — таблица consents с типами: `push`, `whatsapp`, `sms`, `email`, `data_sharing`, `ai_assistant`, `telemedicine`
- EPDS: психологически чувствительный опросник — данные с повышенной защитой
- Security hardening: Migration 027

| **LTV** | Lifetime Value — пожизненная ценность клиента |
